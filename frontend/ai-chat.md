# AI 챗

> 작성일: 2026-10-14
> 상태: `loresentry-frontend` 브랜치 `feat/ai-chat`. mock과 실제 API 모두 동작한다. 실제 API에서는 gateway 허용 목록에 있는 사용자만 쓰고, 나머지는 "AI 챗은 아직 준비 중이에요"를 본다.
> 서버 요구사항: [../AI_CHAT_REQUIREMENTS.md](../AI_CHAT_REQUIREMENTS.md)

작업공간 오른쪽 아래 버튼으로 여는 대화 창이다. 질문하면 AI가 프로젝트의 원고·설정 문서·관계·메모를 모두 읽고, 근거 문서를 칩으로 붙인 답을 스트리밍으로 보여 준다. 원고나 설정 문서의 문장을 드래그해서 바로 물을 수도 있다. AI는 문서를 고치지 않는다.

## 1. 정한 것

목업 후보 세 안(A 코너 창 / B 홈과 대화 / C 넓은 창)을 화면으로 비교해 **B 홈과 대화**로 정했다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 창 | 문서를 가리지 않는 떠 있는 창(`role="dialog"`, `aria-modal="false"`). 바깥을 눌러도 닫히지 않는다 | 원고를 보며 묻고, 드래그해서 묻기 위해 |
| 구조 | 홈(인사·새 대화 입력칸·대화 목록과 검색·추천 질문) → 대화 | 프로젝트에 대화가 여러 개라 목록이 첫 화면에 있어야 한다 |
| 크기 | 기본 380×600. 왼쪽·위 테두리와 왼쪽 위 모서리를 끌어 바꾼다(340×440 ~ 폭 720, 높이는 화면까지). 테두리를 두 번 누르면 기본 크기. 테두리에 포커스를 두고 방향키(Shift는 크게). 크기는 브라우저에 저장 | 오른쪽 아래에 붙어 있으므로 왼쪽·위로만 자란다 |
| 크기 조절 표시 | 테두리에 올리면 창 둘레에 포커스 링이 둥근 모서리를 따라 생기고, 그 테두리 가운데에 짧은 손잡이(4×36), 모서리에는 곡선을 따르는 호가 나타난다 | 둥근 창 가장자리에 곧은 선을 긋는 것은 그림자와 겹쳐 어색했다 |
| 좁은 화면(≤900px) | 아래에서 올라오는 시트. 크기 조절 없음 | |
| 대기 | 답 모양의 뼈대 줄 + "원고와 설정을 모으는 중" → "작품 전체를 읽는 중" + 경과 초 | 첫 토큰까지 수십 초 걸릴 수 있다(매 턴 전체 읽기) |
| 스트리밍 | 새로 온 글자만 흐림에서 선명해지며 들어온다(220ms). 끝에 청록 캐럿. 덜 도착한 `[[` 나 `**` 는 숨긴다 | |
| 근거 | 문서 근거는 종류 색 칩(관계 칩과 같은 12% 물들임), 메모 근거는 회색 "메모 · 제목" 칩. 올리면 인용, 누르면 문서(메모는 메모 화면)를 연다 | 메모는 작가의 작업 노트라 원고의 사실과 구분한다 |
| 답 동작 | 복사(근거는 제목으로 바꿔 복사). 마지막 질문에 연필 → 고쳐서 보내면 그 질문과 답을 바꾼다 | |
| 멈추기 | 생성 중인 대화의 입력칸에만 ■ 버튼. 미완성 답은 남기지 않고 "다시 묻기"를 준다 | 다른 대화의 생성을 보이지 않게 멈추지 않도록 |
| 동시 생성 | 대화마다 따로 돈다. 창을 닫거나 다른 대화로 가도 계속되고, 닫혀 있으면 런처에 링, 끝나면 점 | |
| 지금 보는 문서 | 입력칸 아래 칩으로 보이고 누르면 뺀다 | 답의 초점 힌트 |
| 드래그 질의 | 문서 본문(원고·설정)에서 선택하면 "AI에게 묻기 \| 설명해 줘 \| 관련 설정 \| 앞뒤 흐름". **챗 창에 대화가 열려 있으면 그 대화에, 아니면 새 대화로** (`selection-route.ts`). AI에게 묻기는 인용을 입력칸에 붙이고, 나머지는 바로 보낸다 | 사용자 결정(2026-10-14) |
| 분량 초과 | 작품 자료 글자 수가 한도를 넘으면 런처를 비활성(회색)으로 두고, 누르면 이유와 크기·한도를 보인다. 드래그 막대도 뜨지 않는다 | 사용자 결정. 조용히 잘라 읽고 틀린 답을 내는 일을 막는다 |
| 대화 검색 | 홈 "대화" 아래. 제목·질문·인용·답·근거 제목에서 찾고 일치를 청록 표시(프로젝트 검색과 같은 색). Enter는 첫 결과, Esc는 지우기. 결과를 열면 대화 안에서도 강조하고 첫 일치로 스크롤 | |
| 표식 | 책갈피가 꽂힌 말풍선(`ai-mark.tsx`). 런처는 꽉 찬 면에서 리본을 바탕색으로 오려 냄, 그 밖은 1.75 선 | 흔한 반짝이 대신 "작품에 대한 대화" |
| 추천 질문 | 어느 작품에나 맞는 세 개: 가장 최근 회차, 주요 인물과 연결된 설정, 주인공이 처음 흔들리는 장면 | |

## 3. 서비스 계약

`ChatService`(`src/services/ports.ts`): `availability`, `sessions`, `search`, `createSession`, `renameSession`, `deleteSession`, `messages`, `send(sessionId, input, handlers, signal)`. `send` 의 핸들러는 `onPhase`(gathering·reading·writing), `onCitation(index, citation)`, `onDelta(text)` 이고, 근거는 그 표시보다 먼저 온다. 멈춤은 `AbortSignal`. 서버 API와 SSE 이벤트는 [AI_CHAT_REQUIREMENTS.md §4](../AI_CHAT_REQUIREMENTS.md#4-api-계약).

실제 API 모드에서는 `services/api/chat.ts`가 gateway의 `/projects/{id}/chat/…`·`/chat/sessions/{id}/…`를 부른다. 허용 목록 밖 사용자는 403 `CHAT_NOT_ENABLED`를 받고, 이를 `unavailable`로 옮겨 창이 `PreparingState`("AI 챗은 아직 준비 중이에요")를 보인다. 드래그 막대는 뜨지 않는다. `services/api/unavailable.ts`는 마지막 포트였던 챗이 옮겨 가 지웠다.

## 4. mock으로 보기

- `pnpm dev` → `/login/` → "Google로 계속하기" → "유리 정원의 기록". 12화를 열면 드래그 질의를 볼 수 있다.
- 실제처럼 답하는 것: 추천 질문 세 개와 시드 대화, 12화 문장의 드래그 질문(의도별 답). 그 밖의 질문에는 예시 데이터라는 안내로 답한다.
- 대기 시간은 모으기 0.9초, 읽기 2.6초로 고정이다.
- 분량 초과 화면: 작업공간 주소에 `&chatLimit=1000` 을 붙인다.
- 실패: `&mock=chat.send:fail`.

## 5. 다른 화면에 반영한 것

출시 전이므로 모두 제목 뒤에 "곧 열려요" 표시가 붙는다(`CHAT_LAUNCHED`를 true로 바꾸면 사라진다). 디자인 규칙은 `loresentry-frontend/DESIGN.md`의 AI Chat 절.

- 랜딩: AI 최신화 다음에 AI 챗 장(근거와 함께 답하는 장면, 드래그 질의), 헤더 메뉴.
- 첫 사용 온보딩: 그래프 최신화 다음에 "작품을 아는 AI 챗" 단계. 무대 창 오른쪽 아래에 런처를 다시 그렸다.
- 작업공간 둘러보기: 런처를 원으로 비추는 단계.
- 사용 가이드: "AI 챗" 주제.

## 6. 남은 일

- 새로 고친 뒤에도 서버에서 생성 중인 대화(`messages` 응답의 `generating: true`)를 "답을 쓰는 중"으로 보이고 완료를 기다린다. 지금은 질문만 보이고, 답은 다시 열 때 나타난다.
- 삭제된 문서를 가리키는 과거 근거 칩을 비활성으로 보인다.
- 전체 공개 때 `CHAT_LAUNCHED = true`(랜딩·온보딩·가이드·둘러보기의 "곧 열려요"가 사라진다).
